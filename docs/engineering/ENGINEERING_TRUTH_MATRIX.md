# AUTOVERSE 3D — ENGINEERING TRUTH MATRIX & PROVENANCE CLASSIFICATIONS
**Document ID:** `docs/engineering/ENGINEERING_TRUTH_MATRIX.md`  
**Purpose:** Formal specification of engineering provenance, numerical honesty, and solver classification standards across all AutoVerse modules.

---

## 1. THE AUTOVERSE OPERATING CONTRACT ON TRUTH

1. **Zero Fabricated Results**: If a physical solver did not run on the geometry, no solver result exists. Numbers must never be invented to fill dashboard cards, convergence plots, or report tables.
2. **Every Metric Carries Provenance**:
   - `REAL_VERIFIED`: Directly computed from genuine geometry parsing, topological verification, or native solver run.
   - `REAL_PARTIAL`: Sourced from certified manufacturer technical publications or open datasets with direct citations.
   - `ANALYTICAL_ESTIMATE`: Rapid physical estimation based on boundary layer, lifting-line, or empirical equations. Always displayed with clear formula annotations and validity limits.
   - `PROCEDURAL`: Generated by parametric mathematical algorithms (e.g., procedural car templates). Must be visibly labeled `APPROXIMATE PROCEDURAL GEOMETRY`.
   - `ILLUSTRATIVE`: Educational sketches, diagrams, or visual aids. Must never be presented as engineering evidence.
   - `BLOCKED_ENGINE_UNAVAILABLE`: Returned honestly when an external solver binary (e.g. `simpleFoam`, OpenCASCADE) is not installed or configured on the host.
